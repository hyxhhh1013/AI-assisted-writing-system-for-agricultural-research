## 二、背景与问题

### 2.1 系统简介

「禾书耕文」面向**农业科研**场景的论文写作辅助平台，已具备：选题与大纲、分章节 AI 扩写、文献知识库检索、引用核查、审查与查重、图表与导出等功能。

### 2.2 当前偏差

系统最初目标是提升**初稿写作效率**，但在功能迭代后，完整使用路径接近：

> 填写题目 → 选择方向 → 点击生成 → 等待 → 导出

作者在大纲结构、章节初稿、自动修改等环节**参与不足**，容易给使用者（及评审）造成「一键出论文」的印象，与辅助写作、学术规范要求不符。

### 2.3 线上使用反馈（与产品改造相关但需单独处理）

在实验室 VPS（4 核 CPU / 8GB 内存）部署试运行中，还存在：

- 多用户同时扩写时系统响应变慢；
- 偶发扩写中断、API 报错；
- 部署环境（数据库连接、文献目录路径）配置繁琐。

**说明**：上述问题将通过「稳定性专项」优先缓解；产品交互改造与之并行、互不替代。

## 三、调整目标与四项原则

### 3.1 目标陈述

将交互模型从：

**「人设定参数 → 机器全自动完成 → 人接收结果」**

调整为：

**「人表达思路 → 系统稿 → 给建议/草人审阅修改 → 系统按反馈迭代 → 人定稿」**

### 3.2 四项原则（用于验收）


| 原则   | 含义         | 可观察结果                    |
| ---- | ---------- | ------------------------ |
| 人先机后 | 无实质输入不启动生成 | 扩写前需有草稿要点；大纲需先由人给出章节骨架   |
| 可见可控 | 机器修改对人透明   | 审查结果以「待办清单」展示，作者逐条决定是否采纳 |
| 增量迭代 | 可中途修改方向    | 初稿可编辑后再提交审查；可忽略部分建议      |
| 透明有据 | 建议可核对      | 审查意见关联原文片段；引用可回溯文献       |

## 四、分阶段实施方案

### 阶段 0：稳定性与部署（约 1～2 周，优先）

**目的**：保障实验室多人试用时不频繁宕机，为后续改交互打基础。


| 措施                  | 用户可感知变化                    |
| ------------------- | -------------------------- |
| 限制同时进行的扩写任务数        | 高峰期提示「系统繁忙，请稍后再试」，而非长时间无响应 |
| 默认使用较轻量的「快速预览」模式    | 减少单次点击触发的后台计算量             |
| 部署前自动检查数据库、文献库、密钥配置 | 降低每次上线配置错误                 |
| 扩写失败时保留已生成文字        | 减少「白屏重来」                   |


**本阶段不改变**「必须从草稿开始写」等产品规则（留给阶段 1）。

---

### 阶段 1：人机协作核心（约 2～3 周）

**目的**：从流程上落实「辅助写作」，改动可控、可分批上线。


| 序号  | 内容     | 用户侧变化                                       | 预估工期  |
| --- | ------ | ------------------------------------------- | ----- |
| 1.1 | 扩写入口约束 | 须先输入不少于约 50 字的思路/要点才能生成；按章节给出写作引导           | 0.5 天 |
| 1.2 | 大纲协作   | 作者先填写 3 个以上一级章节标题，AI 仅补全子节与要点               | 1 天   |
| 1.3 | 扩写分步流程 | 先生成初稿 → 作者可改 → **手动**提交审查 → 作者勾选要改的问题 → 再修复 | 3～4 天 |
| 1.4 | 审查清单化  | 审查结果以列表展示（问题类型、原文、建议），非静默自动改全文              | 2 天   |


**阶段 1 结束时的演示能力**：

- 演示「没有干货不能点生成」；
- 演示「AI 只补骨架不全包」；
- 演示「作者决定采纳哪条修改意见」。

---

### 阶段 2：入口整合（约 1～2 周，可选）


| 内容       | 说明                           |
| -------- | ---------------------------- |
| 写作统一在工作台 | 取消与项目脱节的独立「一键扩写页」，写作嵌入项目编辑流程 |
| 编辑器选中辅助  | 对选中段落提供扩写、润色、检查等（与现有能力对齐）    |
| 数据分析免责   | 分析结果页标明「AI 生成，仅供参考」          |


**是否纳入答辩前交付**：建议与老师确认优先级；时间紧可只做 1.1～1.4。

---

### 阶段 3：对话式助手（远期，约 2～4 周，本次不承诺）

在编辑器旁增加可持续对话的 AI 面板（问逻辑、找文献、改措辞等），作为**终局体验**，依赖阶段 1、2 稳定后再做。

---

## 五、实施节奏建议（4 核 / 8GB 服务器）

```text
第 1 周：阶段 0（稳定性）+ 1.1 扩写门槛 + 1.2 大纲骨架（可并行）
第 2～3 周：1.3 分步扩写 + 1.4 审查清单
第 4 周及以后：阶段 2（视答辩节点取舍）→ 阶段 3 远期
```

**里程碑建议**：


| 时间点    | 交付物                  |
| ------ | -------------------- |
| 第 1 周末 | 多人试用不明显卡顿；扩写需先写要点    |
| 第 3 周末 | 完整「生成—审查—选择性修改」流程可演示 |
| 答辩前    | 按老师意见裁剪阶段 2          |


---

## 六、不在本次方案内的事项

- 不更换大模型供应商或重新训练模型；
- 不改动文献知识库的核心检索算法（仅使用方式变化）；
- 不承诺批量自动生成整篇论文；
- 不做移动端适配；
- 阶段 3 对话助手不纳入近期必交付范围。

---

## 七、风险与对策


| 风险              | 对策                         |
| --------------- | -------------------------- |
| 操作步骤变多，同学抱怨「变慢」 | 保留「快速预览」仅生成初稿；深度审查需主动选择    |
| 开发周期超出预期        | 严格分阶段；阶段 2、3 可延后           |
| 改交互后仍卡顿         | 阶段 0 全局限流与默认轻量模式；与产品改造并行   |
| 与「提高效率」目标看似矛盾   | 强调减少返工与合规风险；效率体现在「有据可查的迭代」 |


---

## 八、预期成效（供评估）

1. **合规与形象**：系统明确为写作**辅助**工具，降低学术不端争议空间。
2. **论文质量**：结构由作者主导，AI 负责扩展与提示问题，利于农业科研写作规范。
3. **可演示性**：答辩可展示「作者决策点」，体现研究工作的系统性与可控性。
4. **可维护性**：分阶段实施，避免一次性重构导致项目不可用。

## 九、附录：现状与目标流程对照

### 现状（简化）

```text
题目 + 方向 → AI 生成完整大纲 → 选节 → 一键扩写（自动写+自动审+自动改）→ 导出
```

### 目标（简化）

```text
题目 + 方向 → 作者写章节骨架 → AI 补子节
              → 作者写章节要点 → AI 扩写初稿 → 作者修改
              → 作者提交审查 → 看待办清单 → 勾选后修复 → 导出
```
