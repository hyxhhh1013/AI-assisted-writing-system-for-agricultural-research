二、背景与问题

2.1 系统简介

「禾书耕文」面向农业科研场景的论文写作辅助平台，已具备：选题与大纲、分章节 AI 扩写、文献知识库检索、引用核查、审查与查重、图表与导出等功能。

2.2 当前偏差

系统最初目标是提升初稿写作效率，但在功能迭代后，完整使用路径接近：填写题目 → 选择方向 → 点击生成 → 等待 → 导出。作者在大纲结构、章节初稿、自动修改等环节参与不足，容易给使用者（及评审）造成「一键出论文」的印象，与辅助写作、学术规范要求不符。

2.3 线上使用反馈

在实验室 VPS（4 核 CPU / 8GB 内存）试运行中，还存在：多用户同时扩写时响应变慢；偶发扩写中断；部署配置（数据库、文献目录）繁琐。上述问题将通过「稳定性专项」优先缓解，与产品交互改造并行。

三、调整目标与四项原则

3.1 目标陈述

将交互模型从「人设定参数 → 机器全自动完成 → 人接收结果」，调整为「人表达思路 → 系统给建议/草稿 → 人审阅修改 → 系统按反馈迭代 → 人定稿」。

原则含义可观察结果
人先机后无实质输入不启动生成扩写前需有草稿要点；大纲需先由人给出章节骨架
可见可控机器修改对人透明审查结果以「待办清单」展示，作者逐条决定是否采纳
增量迭代可中途修改方向初稿可编辑后再提交审查；可忽略部分建议
透明有据建议可核对审查意见关联原文片段；引用可回溯文献

四、分阶段实施方案

阶段 0：稳定性与部署（约 1～2 周，优先）

措施用户可感知变化
限制同时进行的扩写任务数高峰期提示「系统繁忙」，而非长时间无响应
默认使用较轻量的「快速预览」模式减少单次点击触发的后台计算量
部署前自动检查配置降低每次上线配置错误
扩写失败时保留已生成文字减少「白屏重来」

本阶段不改变「必须从草稿开始写」等产品规则（留给阶段 1）。

阶段 1：人机协作核心（约 2～3 周）

序号内容用户侧变化预估工期
1.1扩写入口约束须先输入不少于约 50 字的思路/要点；按章节给出写作引导0.5 天
1.2大纲协作作者先填写 3 个以上一级章节标题，AI 仅补全子节与要点1 天
1.3扩写分步流程先生成初稿 → 作者可改 → 手动提交审查 → 勾选要改的问题 → 再修复3～4 天
1.4审查清单化审查结果以列表展示，非静默自动改全文2 天

阶段 1 结束时可演示：没有干货不能点生成；AI 只补骨架不全包；作者决定采纳哪条修改意见。

阶段 2：入口整合（约 1～2 周，可选）

  • 写作统一在工作台，取消与项目脱节的独立「一键扩写页」
  • 编辑器选中段落提供扩写、润色、检查
  • 数据分析页标明「AI 生成，仅供参考」

时间紧可只做阶段 1；是否纳入答辩前交付请与老师确认。

阶段 3：对话式助手（远期，本次不承诺）

编辑器旁可持续对话的 AI 面板，依赖阶段 1、2 稳定后再做。

五、实施节奏建议

第 1 周阶段 0（稳定性）+ 1.1 扩写门槛 + 1.2 大纲骨架
第 2～3 周1.3 分步扩写 + 1.4 审查清单
第 4 周+阶段 2（视答辩节点取舍）→ 阶段 3 远期
时间点交付物
第 1 周末多人试用不明显卡顿；扩写需先写要点
第 3 周末完整「生成—审查—选择性修改」流程可演示
答辩前按老师意见裁剪阶段 2

六、不在本次方案内的事项

  • 不更换大模型供应商或重新训练模型
  • 不改动文献知识库核心检索算法
  • 不承诺批量自动生成整篇论文
  • 不做移动端适配
  • 阶段 3 对话助手不纳入近期必交付范围

七、风险与对策

风险对策
操作步骤变多，抱怨「变慢」保留「快速预览」仅生成初稿；深度审查需主动选择
开发周期超出预期严格分阶段；阶段 2、3 可延后
改交互后仍卡顿阶段 0 全局限流与默认轻量模式
与「提高效率」看似矛盾强调减少返工与合规风险

八、预期成效

  1. 合规与形象：系统明确为写作辅助工具，降低学术不端争议空间。
  2. 论文质量：结构由作者主导，AI 负责扩展与提示问题。
  3. 可演示性：答辩可展示「作者决策点」。
  4. 可维护性：分阶段实施，避免一次性重构导致不可用。

九、附录：流程对照

现状（简化）

题目 + 方向 → AI 生成完整大纲 → 选节 → 一键扩写（自动写+自动审+自动改）→ 导出

目标（简化）

题目 + 方向 → 作者写章节骨架 → AI 补子节 → 作者写章节要点 → AI 扩写初稿 → 作者修改 → 作者提交审查 → 看待办清单 → 勾选后修复 → 导出
