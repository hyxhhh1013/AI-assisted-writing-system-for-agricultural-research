## 一、本周核心工作（6.2 — 6.6）

### 1.1 工程规范与架构整理

- 建立 **L1～L4 文档分层**（`AGENTS.md`、`DOMAIN_INDEX`、API 索引自动生成等）。
- **ENG-PR-023～031** 一批落地：
  - 写作 API 拆为 `pipeline/*` 薄路由 + 阶段模块（ENG-PR-030）；
  - 项目 **references / analysis 增量 PATCH**，禁止全量覆盖；
  - 知识库元数据 **Prisma 为权威源**（ENG-PR-027/028）；
  - UI **fetch → services** 迁移（ENG-PR-020～022）；
  - 工作台 IMRaD **引用溯源侧栏可滚动** 等体验修复。

### 1.2 RAG 与知识库

- RAG **二进制索引、异步加载、检索超时与预热** 持续完善。
- **书目补全、索引修复、引用编号归一化**（越界引用 strip + 前端 warnings）。
- 安全修复：知识库 / PDF **路径穿越**拦截；`proxy` 注入 `x-user-id` 供 API 使用。

### 1.3 质量、审查与 Admin

- **质量模块 Phase 3**、审查 / 查重、Admin 能力增强合入。
- CI：**绿门 check**、lint 策略；部署改为 **手动 PM2**；无 RAG 索引时跳过部分集成测。

### 1.4 生产部署与线上稳定性

| 事项 | 结果 |
|------|------|
| 部署架构 | PM2 + standalone 上传；PostgreSQL Docker `@127.0.0.1:5432` |
| PM2 模式 | **单实例 fork**（避免 cluster 与 Next standalone 冲突） |
| 内存 | `max_memory_restart` **3GB** |
| 扩写 SSE | 超时、fetch 清理，减少中途 Network Error |
| 进程崩溃 | 客户端断开 / `reader.cancel` 未 await 等 **unhandledRejection** 修复 |
| 配置安全 | 部署 **不覆盖服务器 .env**；JWT 变更 **不覆盖 DB 中的 API Key** |
| 备份 | 服务器 **cron 备份** + 本机 pull 脚本 |

### 1.5 产品规划与导师材料（本地完成，建议尽快入库）

- **ENG-PR-080 系列计划**重写：拆 **087（P0 稳定性）+ 080～086 + 088 规划**，登记工程队列 Phase 6。
- **导师确认方案**（产品语言）：定位调整、分阶段实施、请示勾选栏 — 见 `docs/plans/ENG-PR-080-导师确认方案.*`。

### 1.6 技术调研结论（已达成共识）

- **多 API Key**（`DEEPSEEK_API_KEY_2`…）可轮转缓解上游 **429**；**不能替代** 8GB VPS 写作并发控制。
- **ENG-PR-087**（全局限流、默认 fast、失败保留草稿）应优先于 **081 分步 UI**。
- 线上卡顿 = **机器资源 + 管道过重 + 配置错误** 叠加，需「稳定性」与「人机协作」双线并行。
